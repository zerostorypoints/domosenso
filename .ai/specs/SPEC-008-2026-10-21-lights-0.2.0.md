# SPEC-008: `lights` 0.2.0 — room lights that follow the bulbs, lights-on count, battery

Status: approved 2026-10-21 by the maintainer, as one batch (draft 2026-10-21).
Source: SPEC-002 §2.3 (row `lights`), plan Task 19; the maintainer's home lights package (read
2026-10-21).

## Goal

Where wall switches cut the bulbs' power, the bulbs drop off the Zigbee mesh and the Hue bridge's
room group keeps the state it had: a room reads "on" all night with every bulb dead. 0.2.0 renders a
template light per room that counts as on only while one of its bulbs is reachable and on, sends
commands to the Hue group (one broadcast per room), and is unavailable only when the group is. Plus
a count of bulbs that are on and the lowest battery of the Hue accessories.

Stays local in the maintainer's home: the corridor motion light and its illuminance helpers, the
bedside button that turns every light off (one home's layout).

## Devices, integrations

Unchanged from 0.1.0 (Hue bridge, `hue` core). New core platform used: `template` (light, sensor).

## Inputs

Existing, unchanged: `lights`, `lights_all_off` (the Ramka's tiles read these). New, optional:

| input | type | default | note |
|---|---|---|---|
| `rooms` | `list[{group, name, id?}]` | `[]` | `group`: the Hue room group (`light.*`); `name`: the template light's name; `id`: the id part, default the group's object id |
| `battery_sensors` | `list[entity_id]` | `[]` | Hue accessories' battery sensors; none → no battery sensor |

## Provides (additive-only to the manifest; every id equals the maintainer's home today)

| entity | `unique_id` | stability |
|---|---|---|
| `light.room_<id>` (`default_entity_id` pinned, name from `name`) | `room_<id>` | stable |
| `sensor.lights_on` (Hue bulbs on; groups excluded by `is_hue_group`) | `lights_on_count` | stable |
| `sensor.hue_lowest_battery` (`unknown` when every sensor is unavailable) | `hue_lowest_battery` | stable |

The template light keeps the home's behaviour: state from `expand(group's entity_id)`, level and
colour temperature from the group, `min_mireds` / `max_mireds` from the group's Kelvin range,
`set_temperature` passing brightness along when given. The two sensors carry `component: lights`;
the template lights do as well if Home Assistant 2026.9.2 accepts `attributes` on a template light
**(inference: not verified; dropped if `check_config` refuses it)**.

Silent automations: none (no automations).
