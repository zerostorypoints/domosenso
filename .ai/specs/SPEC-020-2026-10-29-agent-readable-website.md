# SPEC-020: domosenso.org readable by AI agents

Status: approved 2026-10-29 (maintainer, in session). Extends SPEC-014 (framework website).
Source: the maintainer asked on 2026-10-29 that personal agents (Claude Duet, Meta Muse, OpenAI dots)
and coding agents find domosenso.org, answer a request with a recipe from its how-tos and send the
person to the catalog; that `llms.txt` and markdown versions of pages stay current with every site
update; and that the README points agents to the site. Research notes are summarised under
"Evidence" below.

## Intent

Someone asks their agent for a home project ("a wall tablet for Home Assistant", "automate my old
awnings"). The agent should come back with a recipe taken from a domosenso.org how-to, fitted to what
the person owns, state honestly what is not supported, and end with the next step: clone the catalog
and run `onboard-home` with the how-to's prompt.

Two readers, both in scope (maintainer, 2026-10-29):

- **Has Home Assistant Container** and Claude Code or Codex: how-to → the branch that matches their
  hardware → that branch's `prompt` → clone and `onboard-home`.
- **Has no Home Assistant yet**: a "start here" recipe: what host it takes, that `onboard-home` can
  install Home Assistant from the home template's `compose.yaml`, and the limits (see Honesty).

Two kinds of agent read the site, and the work serves both:

- Personal agents and chat assistants find pages through a search index and read them as HTML in a
  cloud browser. For them the HTML pages and the indexes matter.
- Coding agents (Claude Code, Codex) fetch `llms.txt` and markdown. Claude Code sends
  `Accept: text/markdown`. They do the installing and need the exact recipe and prompt.

## Goals

1. `/llms.txt`, `/llms-full.txt` and a markdown version of each content page, **generated by
   `next build` from the same data the HTML is rendered from**, so that any site update refreshes
   them and they cannot drift.
2. A test that fails the build or CI when they do not match the published content.
3. HTML pages that state the "no Home Assistant yet" route, which today only the README covers.
4. The README's "For AI agents" block points to `https://domosenso.org/llms.txt` and the how-tos.
5. The site is crawlable by search and agent bots, and indexed by Bing and Google. Deliverable
   (our call): a one-off report after the first deploy in `docs/research/`, with the Bing and
   Search Console readings and the Brave search, repeated once a week later; no scheduled job.
   Whether real crawlers pass Cloudflare is read by the maintainer in AI Crawl Control, which
   counts requests per crawler; no Cloudflare credentials are requested for this.

## Non-goals

- A git-free install (Homebrew formula, Claude Code plugin marketplace). Not planned (maintainer,
  2026-10-29): Domosenso assumes its users know GitHub. The site and `llms.txt` state git and a
  GitHub account as prerequisites, as the README does, and do not offer another route.
- An MCP server or `/.well-known/` agent manifests: MCP server cards are a draft (SEP-2127) with no
  settled path.
- Content negotiation on `Accept: text/markdown`. Our call: the site is a static export on
  Cloudflare Pages with no functions, and markdown on demand would need a Pages Function or a paid
  Cloudflare feature. `.md` URLs plus `<link rel="alternate" type="text/markdown">` cover the
  agents that look for markdown. Revisit if logs show agents asking for it.
- New schema.org types. The existing `HowTo` JSON-LD stays; measured effect on AI answers is nil
  (Evidence).
- The commercial site (domosenso.com, repository `domosenso-web`) and the home repository
  (`domosenso-zollweg12`). Nothing from a real home goes into any generated file.

## Anti-goals

- **An agent overselling Domosenso.** The generated text must carry the limits as plainly as the
  capabilities: every how-to branch with `supported: no` or `coming-soon` appears with its reason or
  issue; host limits appear in `llms.txt` itself, not only behind a link.
- Drafts leaking. Draft how-tos and journal entries must never appear in a production `.md`,
  `llms.txt` or `llms-full.txt`, exactly as for HTML (`e2e/drafts.spec.ts`).
- Markdown copies competing with the HTML pages in search results.
- Hand-maintained agent files. Nothing under `website/public/` is written by hand for this.

## Design

### Files the build writes

All are static route handlers (`export const dynamic='force-static'`), the pattern of
`src/app/journal/feed.xml/route.ts`, reading `src/generated/*.json` and `@/lib/*` server modules.
They are server-only like `howtos.json` (README, "Visual catalog").

**`/llms.txt`** follows the llmstxt.org format (H1, blockquote summary, H2 sections of links with
one-line notes). Content, in this order:

1. What Domosenso is, in two or three sentences: an Apache-2.0 catalog of tested Home Assistant
   components plus agent skills; your agent (Claude Code or Codex) installs them into your own home
   repository; you approve every write.
2. **Start here**, the two routes above, each with the commands (clone, `uv sync`, start the agent,
   `onboard-home`) and the get-started URL. Commands come from one shared module that the
   get-started page also renders, so they cannot differ. They clone `main` with its tags and do
   not check out `frameworkCommit` (maintainer, 2026-10-29): components are pinned by their own
   tags, and a detached checkout of the publication commit leaves users behind `main`'s skills.
3. **Limits**: Home Assistant Container only (HAOS not covered); Synology DSM with Container Manager
   is the tested host, other Docker hosts untested; Windows only through WSL2, untested; installing
   Home Assistant on a NAS through `onboard-home` not yet tried (tried on a local container).
   Source (our call): `tools/export_website.py` exports the README's "Prerequisites" at
   `frameworkCommit` into a generated JSON, checked by `--check`, like the other published
   documents. Reading `../README.md` at build time would publish unreviewed text from `main` and
   would not rebuild on a README-only commit (the Pages build watches `website/*`). The limits
   therefore lag `main` until the next publication bump, as all published content does.
4. **How-to guides**: every published how-to, link to its `.md`, its `description`, and per branch
   one line `situation → supported` (`yes`, `coming soon: <issue>`, `no`).
5. **Components**, **Hardware**, **Docs**: each entry linked to its `.md`, one line each.
6. **For coding agents**: the rules of the README's "For AI agents" block (clone with tags, run
   `onboard-home`, home in its own folder, never change the catalog in place, stop at every
   question), linked to `AGENTS.md` on GitHub.
7. Optional section: journal, releases, contribute.

**`/llms-full.txt`**: the same header and Start here and Limits, then the full markdown of every
published how-to, the get-started page, and every component page, separated by their URLs.
Size is not capped; at today's 6 how-tos and 10 components it is small.

**A `.md` per content page**: how-tos, components, devices, docs, get-started; journal entries
too, since they are already markdown. For a how-to the `.md` contains: title, description,
`updated`, the body, and every branch as a section with situation, needs, wiring, supported, and
for `yes` the prompt in a fenced block headed "Prompt for your coding agent", for `coming-soon` the
issue link. Sources (pinned GitHub URLs) at the end. The HTML page's canonical URL is on the first
line.

URL scheme: the builder's choice, constrained to: one stable URL per page, linked from that page's
`<head>` as `<link rel="alternate" type="text/markdown" href="…">`, served with
`Content-Type: text/markdown; charset=utf-8`, and carrying an HTTP `Link: <html url>;
rel="canonical"` header (Cloudflare Pages `public/_headers`) so the copy does not compete with the
HTML in search. Shape: `<page path>index.md`, for example `/how-to/<slug>/index.md`. A spike on
2026-10-29 confirmed that a `force-static` route handler at `src/app/how-to/[slug]/index.md/route.ts`
with `generateStaticParams` exports `out/how-to/<slug>/index.md`.

`.md` URLs stay out of `sitemap.xml`. `robots.txt` is unchanged (`Allow: /`).

### One source for HTML and markdown

The how-to, device, doc and journal pages already render markdown bodies with `react-markdown`.
The markdown generators live in `src/lib/` next to the existing loaders (`howto.ts`, `content.ts`,
`docs.ts`, `catalog.ts`) and take the same objects the pages take. Component pages are built from
`catalog.json` fields; their `.md` is a plain rendering of the same fields (summary, requirements,
integrations, tested versions, tested homes, limitations, inputs, source and upgrade links),
keeping SPEC-014's rule that missing evidence stays missing. `host.installs` is left out: the HTML
does not show it and it lists `haos` for most components, which would contradict the Limits.

### HTML changes

- Get-started gets a "No Home Assistant yet?" section with the second route and its limits.
  Today it lists Home Assistant Container under "Before you start" as if required.
- Get-started drops `git checkout ${frameworkCommit}` and clones `main` with tags, from the shared
  command module above. README, get-started and `llms.txt` then give the same commands; a test
  checks that the README's "Start in 10 minutes" commands match the module.
- The homepage's first paragraph already states what Domosenso is; no change unless the builder
  finds the plain-text reading (what a cloud browser extracts) loses it.
- Each content page gets the `rel="alternate"` link above.

### README

`README.md` "For AI agents" adds: recipes for specific projects are the how-tos at
`https://domosenso.org/how-to/`; the index for agents is `https://domosenso.org/llms.txt`.
`website/README.md`: document the generated files and their tests under "Updating public
content", and remove the stale "Keep previews private until repository publication" (the
repository is public).

### Off-site steps

| step | who | when |
|---|---|---|
| Cloudflare dashboard, AI Crawl Control: search crawlers, agent crawlers and user-triggered fetchers allowed; "Block AI bots" off; Bot Fight Mode does not challenge verified bots | maintainer (dashboard) | before or with the release |
| Submit `https://domosenso.org/sitemap.xml` in Bing Webmaster Tools (property verified) | agent, with the maintainer's go-ahead | after deploy |
| IndexNow: already automated on `main` (`.github/workflows/indexnow.yml`, `tools/website_changes.py`, `tools/indexnow.py`, #85, #93); `website_changes.py` gains the agent files of a changed page | builder | with the implementation |
| Google Search Console: sitemap present (property `sc-domain:domosenso.org` verified) | agent reads, maintainer approves a submit | after deploy |
| Brave: search for the site and record whether the how-tos are indexed (Claude's web search uses Brave) | agent | after deploy, and again a week later |

### Tests

- Jest (`src/lib/*.test.ts`): each generator against fixtures: a draft how-to is absent; every
  branch appears with its support state; a `yes` branch carries its prompt; `coming-soon` carries
  its issue; component markdown keeps missing evidence missing.
- E2E or a post-build check on `out/`:
  - every published how-to, component, device and doc in `sitemap.xml` has a `.md` that exists and
    is linked from `llms.txt`, and nothing in `llms.txt` points to a missing file;
  - every content HTML page has the `rel="alternate"` link and it resolves;
  - `e2e/drafts.spec.ts` extended to `.md`, `llms.txt` and `llms-full.txt`;
  - the Limits section in `llms.txt` contains each limit from the README source.
- README "Public acceptance checks" gains `curl -I` lines for `/llms.txt`, one how-to `.md`
  (content type and canonical `Link` header).
- The `domosenso-website-audit` skill's checklist gains: generated agent files current.

## Evidence (research 2026-10-29)

Sources: [Claude Duet](https://claude.com/product/claude-duet),
[Meta Muse (AP)](https://www.pbs.org/newshour/nation/meta-launches-personal-ai-agent-muse-to-help-with-everyday-tasks),
[OpenAI dots (TNW)](https://thenextweb.com/news/openai-dots-always-on-ai-agents-cloud-computers-devday),
[OpenAI bots](https://developers.openai.com/api/docs/bots),
[Anthropic crawlers](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler),
[Ahrefs llms.txt study](https://ahrefs.com/blog/llmstxt-study/),
[Ahrefs schema study](https://ahrefs.com/blog/schema-ai-citations/),
[Checkly markdown negotiation](https://www.checklyhq.com/blog/state-of-ai-agent-content-negotation/),
[Cloudflare defaults](https://blog.cloudflare.com/content-independence-day-ai-options/),
[Google AI features](https://developers.google.com/search/docs/appearance/ai-features).
Product facts about Duet, Muse and dots come from press coverage.

- Claude Duet (preview 2026-10-21, US Pro/Max), Meta Muse (US), OpenAI dots (not offered in the
  EEA, UK or Switzerland): cloud computers with browsers; none publishes its own crawler name.
  Inference: they find pages through their parent assistant's search and read HTML.
- Indexes: Claude web search uses Brave; ChatGPT its own index plus Bing (press, not stated by
  OpenAI); Perplexity its own; Google AI Mode Google's.
- `llms.txt`: Ahrefs (2026-06): 97 % of files got no requests; most fetches by GPTBot and Claude
  Code. Google needs no AI files. Markdown negotiation (Checkly, 2026-02): Claude Code, Cursor,
  OpenCode send `Accept: text/markdown`; Codex, Gemini CLI, Copilot do not.
- Schema.org: Ahrefs (2026-05), 1,885 pages: no measurable rise in AI citations after adding JSON-LD.
- Cloudflare since 2026-09-15 may block agent crawlers by default on some zones; requests from the
  maintainer's Mac with spoofed crawler user agents got 200, which does not prove real crawlers
  pass (Cloudflare verifies by IP and signature).
- domosenso.org on 2026-10-29: server-rendered HTML, `HowTo` JSON-LD, sitemap, `Allow: /`,
  `/llms.txt` 404, no markdown. Each how-to branch with `supported: yes` already has a `prompt`
  shown under "Tell your agent".

## Out of scope

Git-free install; MCP; paid Cloudflare markdown conversion; translations (the site is English);
outreach (Home Assistant forum, Reddit, awesome lists), which the research ranks above `llms.txt`
for being recommended but is the maintainer's to do.

None. Note (2026-10-29): `tools/indexnow.py` records that Cloudflare answers the default
Python-urllib user agent with 403, so bot rules are active on the zone; the AI Crawl Control check
above is not a formality.
